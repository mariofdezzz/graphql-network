# GitHub Labels Management

## 📋 Standard Labels

This project uses the following labels to categorize issues:

### 🐛 Bugs
- **bug** - Something isn't working correctly
- **regression** - A bug introduced in recent versions

### ✨ Features
- **enhancement** - An improvement or new feature
- **feature-request** - Formal feature request

### 👥 Community
- **good first issue** - Good for new contributors
- **help wanted** - Community help is wanted
- **discussion** - Topic for discussion or debate

### 🏷️ Status
- **wontfix** - Will not be implemented
- **duplicate** - Duplicate of another issue
- **invalid** - Invalid or out of scope

### 🎯 Priority
- **priority-critical** - Must be fixed immediately
- **priority-high** - High priority
- **priority-low** - Low priority

## 🔄 Label Workflow

1. **New issue** → Assign `bug` or `enhancement`
2. **Under review** → Add `discussion` if clarification is needed
3. **Confirmed** → Add priority if necessary
4. **Resolved** → Close the issue

## 💡 Label Usage Guide

- Each issue should have at least one label
- Bugs always get `bug`
- Features always get `enhancement`
- Use priority labels only when necessary
- Duplicates get `duplicate` + the original label

---

**Note**: Labels can be created and managed directly in the "Labels" section of GitHub.
